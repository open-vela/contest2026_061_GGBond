# WristSpace：基于 openvela 手表的空间化 AIoT 交互系统

## 一、作品简介

WristSpace 是一个面向手表端快应用的空间化 AIoT 交互系统。项目把“空间指向、微手势、AI 动作学习、设备联动”组合成一套完整流程：用户先在手表端选择空间候选设备，再通过翻腕、上摆、下摆、顺时针、逆时针等动作完成控制；当默认动作不够用时，可以为设备指令采集 10 组多模态样本，并由 PC Mock 上位机模拟 EMG 与 IMU 数据完成训练、识别和同步。

当前版本重点解决两个问题：第一，传统手表控制智能家居时依赖屏幕点击，操作路径长；第二，单纯依赖九轴姿态容易误触。项目采用“空间候选设备 + 指令动作绑定 + 置信度门控”的方式，让手表既能快速控制设备，也能解释每次 AI 判别为什么触发或不触发。

## 二、选题方向

选题方向：快应用 / 手表应用创新。

选择该方向的原因是，本项目的核心交互发生在 openvela 手表端：手表不是简单的遥控器列表，而是作为空间 AIoT 控制入口，负责候选设备显示、动作绑定、训练状态、识别结果、安全门控和设备执行反馈。PC 端作为上位机与 Mock 数据中转站，承担当前阶段的数据输入、训练调试和同步验证，后续可以平滑替换为单片机、真实 EMG 采集模块和 IMU 传感器输入。

## 三、目录结构

- `quickapp/WristSpace/` — openvela 手表端快应用工程，包含页面、设备管理、动作绑定、AI 学习展示、PC 同步轮询与矩形表盘适配逻辑。
- `pc/Aiot_PyCharm/` — PC 上位机工程，包含 HTTP 服务、Mock 指令发送、设备配置同步、10 组动作数据采集、轻量训练识别和调试界面。
- `scripts/` — 一键运行脚本，负责启动 PC 服务、编译或部署 RPK、启动 openvela 模拟器并运行手表应用。
- `docs/` — 项目提交资料，包括技术报告、运行说明和报告截图素材。
- `docs/images/` — 文档中使用的界面截图和架构图。
- `logs/` — AI Coding、调试记录和运行日志归档目录，便于补充完整开发过程证据。

## 四、运行方式

### 方式一：PC + AIoT 一键运行

在 PowerShell 中执行：

```powershell
cd E:\WristSpace\quickapp\WristSpace
npm install
npm run demo:all
```

该命令会先执行 `npm run build`，然后启动 PC 上位机服务，再启动矩形 openvela 模拟器并部署当前手表快应用。

### 方式二：分别运行 PC 和 AIoT

先启动 PC 上位机：

```powershell
cd E:\WristSpace\pc\Aiot_PyCharm
python main.py
```

再启动手表端矩形模拟器：

```powershell
cd E:\WristSpace\quickapp\WristSpace
npm install
npm run demo:rect
```

运行后，PC 端按钮、键盘输入、Mock 多模态数据会通过 HTTP JSON 与 AIoT 手表端同步。AIoT 端会显示当前设备、设备状态、动作绑定、AI 学习流程和安全门控结果。

### 常用调试命令

```powershell
cd E:\WristSpace\quickapp\WristSpace
npm run build
npm run demo:rect
```

如果模拟器已经被 AIoT IDE 内嵌调试占用，需要先关闭内嵌虚拟设备，再执行 `npm run demo:rect`。

## 五、AI Coding 使用说明

本项目开发过程中使用 AI 辅助完成需求拆解、交互流程梳理、openvela 快应用页面实现、PC 上位机联调、Mock 数据协议设计、动作训练流程设计、界面布局迭代和提交文档整理。

AI 主要参与了以下环节：

- 需求拆解：将“空间指向 + 微手势 + 米家联动”的想法拆成候选设备、动作控制、设备管理、动作绑定、采集训练、识别执行、安全门控几个闭环。
- 方案设计：从单纯九轴手势控制扩展为 EMG + IMU 多模态动作识别，并保留真实传感器和单片机接入入口。
- 编码实现：完成 AIoT 手表端页面、PC 上位机、HTTP 同步协议、训练样本限制、识别输入、设备动作绑定和运行脚本。
- 调试优化：针对白屏、黑屏、按钮无响应、页面遮挡、矩形表盘适配、PC 与 AIoT 状态不同步等问题进行逐轮修正。
- 文档整理：根据技术报告模板整理作品介绍、系统架构、AI 能力展示、运行方式和未来扩展路线。

完整对话与过程日志可整理放入 `logs/` 目录，用于展示 AI Coding 的真实协作过程。

## 当前能力边界

已实现能力：

- openvela 手表端快应用页面与矩形表盘适配。
- PC Mock 上位机与手表端 HTTP 双向同步。
- 默认设备控制：客厅灯、空调、窗帘、音箱等。
- 新增设备、删除设备、设备动作配置和同步。
- 默认动作与自定义动作绑定逻辑。
- 每个动作固定 10 组数据采集，采满后锁定采集入口。
- PC 端训练、识别输入和置信度门控演示。
- AIoT 端 AI 学习、训练状态、识别结果和可解释决策展示。

后续扩展方向：

- 接入真实 IMU 与 EMG 采集模块。
- 将 PC Mock 数据源替换为单片机串口、BLE 或网络输入。
- 对接真实米家设备控制 API。
- 将训练后的模型参数迁移到端侧轻量推理流程。
- 增加震动反馈和误触撤销策略的真实硬件实现。
